## 4. 关键 Bug 实证（带文件名:行号）

### 4.1 〔阻断级 / CRITICAL〕3D 地表视图挂载崩溃 —— 方法名与函数名不匹配

- **现象**：从菜单/殖民地/星系任意入口进入 `ground`，路由活动视图停在 `menu`，控制台报 `路由失败 TypeError: this._refreshOperaChip is not a function`（`GroundView.js:735`）。
- **根因**：`GroundView._setHead` 在 `GroundView.js:735` 调用 `this._refreshOperaChip()`，但该类上**从未定义**此方法；实际的“行星灵魂徽标头栏芯片刷新”实现被抽成**模块级导出函数** `refreshGroundOperaChip(view)`（`GroundView.js:4562-4568`，注释明示 `doc52 §Task 52.2 GroundView 行契约`）。调用方的方法名与实现函数名脱节，导致每次 `_setHead`（含 `mount`、`_build` 自由探索 `:951`、任务 `:1321`）必崩。
- **影响**：§3.8 整章（外骨骼移动、三模态科考面罩 `V`、工程采掘 `5/F/[ ]`、巨兽讨伐、遗迹解谜）**100% 不可游玩**；共创赛道 F 载体缺失；GAP-03 / Gate4 / SURF-01 直接不达标。
- **修复建议（一行级）**：在 `GroundView.js:735` 将 `this._refreshOperaChip();` 改为 `refreshGroundOperaChip(this);`，并在文件顶部 `import { refreshGroundOperaChip } from './...'`（或就近定义 `this._refreshOperaChip = () => refreshGroundOperaChip(this)`）。
- **证据**：`src/ui/screens/GroundView.js:672-673`（创建 `this.headOperaChip` 元素）、`:733-735`（`_setHead` 调用不存在的方法）、`:4558-4568`（真正的 `refreshGroundOperaChip` 实现）、`playtest_result.json:screenTour`（failed:["ground"]）、`diagnostics_result.json:warnings`（×4 同错）。

### 4.2 〔高级 / HIGH〕命令契约 ID 类型不一致 —— `ExcavateSubterraneanLayer` / `ConfigureFleetDoctrine`

- **现象**：以真实实体 ID 派发这两条命令被拒：
  - `ConfigureFleetDoctrine({empireId:"fac_553",...})` → `"SO: ConfigureFleetDoctrine.empireId 必须为有限整数（实测 fac_553）"`
  - `ExcavateSubterraneanLayer({planetId:"plt_101",...})` → `"SO: ExcavateSubterraneanLayer.planetId 必须为有限整数（实测 plt_101）"`
- **根因**：`commandSchemas.js` 中这两条将 ID 声明为 `type:'number'`（`ExcavateSubterraneanLayer.planetId` 见 `:57`；`ConfigureFleetDoctrine.empireId` 见 `:129`），而**运行时全部实体 ID 都是字符串**（`fac_553`/`plt_101`/`flt_563`/`col_559`）。校验逻辑 `commandSchemas.js:245-247`（`!Number.isInteger(v)`）对字符串直接拒绝。其余 18 条命令契约使用字符串 ID，唯独这两条写成整数——属于契约内部不一致。
- **影响**：§3.2 的“Layer 3 深层地壳掘进 Tier 1~3”与 §3.4 的“巡逻司令部三滑块学说应用”**无法通过标准 `app.dispatch` 路径驱动**；若 UI 也直接传字符串 ID，则对应按钮同样失效。
- **修复建议**：将这两条 `requiredFields` 的 `type` 由 `'number'` 改为 `'string'`（与全局 ID 约定一致）；或在命令层做 ID 归一化。
- **证据**：`src/domain/world/commandSchemas.js:53-57`、`125-129`、`243-251`；`playtest_result.json:commands`（failed 两条）；`diagnostics_result.json:contract`。

### 4.3 〔信息级 / INFO〕外交 S7 子容器惰性初始化（设计如此，但建议预置）

- `spaceOperaState.landsraad` / `palaceEspionage` / `commissions` / `endgameCrisis` / `unityTreasury` 由 `ensureS7State`（`galacticSenateAndCrisisArc.js:192-209`）在“首次触达 S7 或月度钩子”时补齐，而非 `activateSpaceOperaCampaign` 激活时创建。新局首帧 `Object.keys(spaceOperaState)` 仅含 10 个基础键（无 `landsraad`）。
- 这是 CHK-00-04 冻结契约的有意设计（保持顶层键集稳定），UI 也做了缺失兜底（`DiplomacyView.js:409/413` 回退 `{}`）。**不是 Bug**，但建议在激活期预置空容器，避免首帧 `so.landsraad` 为 `undefined` 带来的可读性/调试困惑。

### 4.4 〔待核实 / INFO〕工业关注度字段未直接暴露在 colony 实体

- 探针读取 `colony.industrialAttention` 与 `colony.radicalCellActive` 均为 `undefined`（驱动 branchA 的 `before/after` 均为 `{}`）。§3.3 描述的“工业关注度累计→≥7 触发激进潜伏支部”状态面在 colony 实体上不可直接观测；该功能可能经 `spaceOperaColonyBridge.js` 动态计算而非持久字段。**建议核实**该机制是否已实装及其状态存放位置。
