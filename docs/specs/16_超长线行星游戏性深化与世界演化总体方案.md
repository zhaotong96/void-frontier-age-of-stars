# VOID FRONTIER: AGE OF STARS

## 超长线行星游戏性深化与世界演化总体方案

### 一、战略判断：当前真正缺少的不是内容数量，而是行星上的「可持续活动系统」

我认为，你对当前游戏的判断是准确的，而且问题比委托书列出的四类短板还要深一层。

《无垠边疆》目前已经具备相当扎实的工程底座：委托书记录了 608 颗行星、三维连续地形、18 套主题视听、地表工程建造、基础站点战斗，以及宏观银河战略与微观地表玩法的初步连接。但这些属于世界可被生成、被访问、被渲染、被操作的能力，不等于世界已经具备丰富的游戏性。

必须明确区分以下几个概念：

| 层级   | 解决的问题                    | 玩家实际感受            |
| ---- | ------------------------ | ----------------- |
| 世界规模 | 有多少星系、星球、地形区域            | 世界看起来很大           |
| 内容密度 | 每个区域有多少可发现、可交互对象         | 到处有东西可看、可做        |
| 系统深度 | 对象之间是否存在规则、依赖与反馈         | 玩家需要理解、规划和决策      |
| 状态演化 | 玩家行为是否改变环境、生态、经济与社会      | 世界会记住玩家做过的事       |
| 涌现体验 | 多个系统组合后能否产生非预设事件         | 玩家会遇到意料之外但合乎逻辑的故事 |
| 长期目标 | 是否存在持续数小时、数十小时乃至数百小时的目标链 | 玩家有理由反复回到同一颗星球    |

真正的内容丰富，是让一颗行星从「可供访问的地图」变成「值得长期经营、探索、研究、改造和争夺的复杂世界」。

因此，我不建议把本轮开发组织成五个互不相关的大型功能项目。更合理的方向，是建立一套统一的行星世界模拟框架，让生态、工业、灾害、殖民地、考古、军事等系统共享同一套世界状态、资源流、事件流和玩家行为记录。

这会带来一个重要变化：

> 玩家不是来到一颗星球上，依次完成扫描、采矿、建造、战斗四种任务；而是来到一个有自身运行规律的世界，通过自己的行为介入它，逐步形成一套属于自己的行星级产业、科研、殖民和防御体系。

这才是从「前哨站雏形」走向真正星际沙盒的关键。

### 三、重新定义产品目标：让每颗行星成为一个独立运行的「异星世界」

我建议将《无垠边疆》的行星系统正式定义为：

Planetary Living World System（行星生命世界系统）

核心不是给每颗星球配置一组 POI，而是让每颗星球拥有自己的自然规律、生态系统、资源循环、历史遗迹、社会结构和发展可能性。

一颗星球的价值应该由三个层面共同构成：

## 第一层：自然世界（Natural World）

不依赖玩家，星球本身就存在的东西。

生物、植被、矿脉、地貌、气候、地下结构、自然灾害、生态关系。

## 第二层：文明世界（Civilized World）

历史遗留、外来文明和玩家建立的社会。

古代遗迹、失联设施、殖民聚落、工业基地、交通设施、军事设施、贸易活动。

## 第三层：演化世界（Evolving World）

自然与文明相互作用，持续产生新状态。

生态变化、资源枯竭、环境污染、技术突破、人口迁移、灾害、战争、产业升级。

这三层必须互相影响。

例如：

- 玩家过度抽取地下水，导致湿地萎缩，原生生物迁移，生态研究价值下降。
- 某种菌类能够分解有毒矿物，玩家可以研究它并建立生物净化产业。
- 玩家重新启动一座古代气象控制站，虽然获得了天气控制技术，却可能同时唤醒其防御系统。
- 一场长期磁暴破坏了殖民地的电力设施，工业生产中断，居民产生不满，贸易航线也受到影响。
- 玩家在地表建立离子防御阵列后，该星球从普通资源殖民地变成战略防御节点。

如此一来，同一颗星球就拥有多种发展方向，不再是完成一个任务之后便失去意义。

#### 3.1 不应该要求 608 颗星球全部达到相同的内容密度

这点非常重要。

如果把 608 颗星球全部设计成包含生态、考古、城市、完整工业、军事、剧情的巨型综合玩法，项目规模会失控，程序化内容也会产生严重重复。

正确做法是进行行星内容等级分布（Planetary Content Tiers）。

| 等级     | 建议比例 | 608 颗星球示例 | 产品定位                     |
| ------ | ---- | --------- | ------------------------ |
| S：旗舰世界 | 10%  | 约61颗      | 高密度人工设计内容，完整生态、考古、工业和剧情链 |
| A：特色世界 | 25%  | 约152颗     | 具有鲜明玩法身份，2～3 个主要内容系统相互作用 |
| B：功能世界 | 50%  | 约304颗     | 一项主要玩法、一项辅助玩法、稳定资源与事件循环  |
| C：边疆世界 | 15%  | 约91颗      | 空旷、孤立、危险或神秘，提供稀有发现和战略价值  |

以上是建议的内容配置目标，不是要求一次性完成全部星球。

C 级世界也不应该毫无内容。它可以是一颗极其荒凉、只有一座废弃探测器和某种奇异地质现象的星球。关键是这种贫瘠本身应该具有设计意义。

#### 3.2 每颗星球必须拥有自己的 Gameplay Identity

我建议引入行星玩法身份系统。

每颗星球由以下部分共同确定：

| 属性                      | 作用     | 示例              |
| ----------------------- | ------ | --------------- |
| Primary Role            | 主要玩法身份 | 深空科考、矿业、生态科研、考古 |
| Secondary Role          | 次要玩法方向 | 军事前哨、农业、能源、贸易   |
| Environmental Signature | 独特环境机制 | 硫酸雨、极夜、潮汐、高压    |
| Resource Signature      | 关键产出   | 超导矿、耐腐蚀材料、生物质   |
| Historical Signature    | 历史身份   | 先驱者遗址、失联舰队、古代巨构 |
| Strategic Hook          | 宏观价值   | 舰队补给、轨道防御、特殊科技  |

例如：

硫雾沼泽不应该只是一个黄绿色地表。

它的身份可以是：

- Primary Role：生物化学与生态研究。
- Secondary Role：耐腐蚀工业。
- Environmental Signature：酸雾、硫化气体、爆燃沼气。
- Resource Signature：特殊挥发物、生物质、耐腐蚀材料。
- Historical Signature：古代地下水循环设施。
- Strategic Hook：生物滤芯、特殊药物、污染治理技术。

这意味着玩家来到这颗星球，并不是为了看看黄色天空，而是为了获得其他星球无法提供的技术和工业能力。

#### 3.3 星球内容需要有不同的时间尺度

不能让所有活动都围绕一次性任务组织。

| 时间尺度    | 活动类型               | 玩家目标     |
| ------- | ------------------ | -------- |
| 1～5分钟   | 扫描、采样、调查           | 获得即时发现   |
| 5～30分钟  | 追踪生物、寻找资源、调查遗迹     | 完成局部目标   |
| 30～90分钟 | 建立小型前哨、修复设施、处理灾害   | 获得阶段性收益  |
| 数小时     | 建立生态研究站、完成工业链、开发遗迹 | 形成长期资产   |
| 数十小时    | 行星产业升级、生态治理、社会发展   | 形成稳定殖民世界 |
| 数十至数百小时 | 行星体系间贸易、技术垄断、军事控制  | 形成银河战略优势 |

这里的时间指现实游玩时长的设计目标，不是游戏内时间。

玩家应该能够在同一颗星球上不断切换短期任务和长期目标。

### 四、五大核心支柱：从孤立功能升级为完整玩法系统

## 支柱一：异星生态科学与深空考古

#### 4.2 建立轻量级生态模拟（Ecological Simulation）

千万不要为每一片草、每一棵植物、每一只动物都创建一个持久化模拟实体。

这既不符合 Web 单线程模拟的条件，也不符合每颗星球增量存档不超过 50KB 的要求。

15_无垠边疆超长线演化开发调研任务委托书.md



我建议采用：

区域生态斑块（Ecological Patch）+ 物种种群统计（Population Aggregate）+ 局部表现代理（Visual Agents）。

举例：

一颗星球划分为若干生态区域：

- 北部荧光森林
- 东部湿地
- 南部硫化湖
- 西部岩石荒原
- 中部地下洞穴

每个区域只保存关键生态状态：

```
{
  id: "bio_patch_01",
  biomeId: "biolume_forest",

  biomass: 72,
  soilNutrients: 54,
  waterLevel: 68,
  contamination: 3,

  speciesDensity: [
    ["flora_glow_01", 0.82],
    ["fauna_grazer_01", 0.48],
    ["fauna_predator_01", 0.12]

  lastUpdateTick: 0
```

注意，这只是建议的数据模型，不是要求把代码直接照搬。

实际模拟中：

- 植物密度受水分、温度、营养物质和光照影响。
- 草食动物密度受食物资源和繁殖条件影响。
- 掠食者密度受猎物数量影响。
- 毒性灾害会改变物种存活率。
- 工业污染会改变植被和微生物环境。
- 玩家引入的新物种可能改变当地生态平衡。

核心计算可以使用简化的种群模型：

\\[ \Delta N_i = B_i-D_i+M_i+ \sum_j I\_{ij} \\]

其中：

- \\(B_i\\)：繁殖增长。
- \\(D_i\\)：死亡损失。
- \\(M_i\\)：迁徙净变化。
- \\(I\_{ij}\\)：其他物种、资源、环境带来的交互影响。

不需要进行真实的生物学仿真。重点是让游戏规则具有可解释性，并能够产生玩家能感知的结果。

#### 4.3 建立物种基因与分类图鉴系统

每种物种应该拥有一组稳定的程序化特征。

| 特征                | 示例                        | 对 Gameplay 的作用 |
| ----------------- | ------------------------- | -------------- |
| Trophic Role      | Herbivore、Predator        | 决定生态位置         |
| Temperature Range | -80～20°C                  | 生存温度           |
| Water Dependency  | 0.2～0.9                   | 水资源需求          |
| Activity Cycle    | Day / Night               | 活动时间           |
| Mobility          | Ground / Flying / Aquatic | 运动类型           |
| Diet Tags         | Flora、Mineral、Other Fauna | 食物来源           |
| Toxicity          | 0～100                     | 毒性与危险          |
| Symbiosis Tags    | Fungal、Root、Bacteria      | 共生关联           |
| Genetic Traits    | 低温耐受、抗辐射等                 | 科研和育种方向        |

图鉴不应该只是发现后解锁一张图片。

建议每种生物具有四层发现状态：

1. Observed：首次观察，记录外观、活动规律。
2. Identified：识别分类，了解基本习性。
3. Analyzed：获得样本并分析生物结构。
4. Mastered：掌握关键特征，解锁科研、培育或工业应用。

玩家可以通过不同方式获取研究进度：

- 远距离扫描。
- 跟踪迁徙路线。
- 收集排泄物、组织、卵、孢子等样本。
- 在不同环境下观察其生存能力。
- 研究捕食或共生行为。
- 将样本带回实验室分析。

这里必须有一个非常重要的设计：每个物种的研究价值不仅在于它是什么，更在于它能够解决什么问题。

例如：

- 一种耐辐射真菌，可以用于核污染土地修复。
- 一种高压海洋生物，可以提供特殊弹性蛋白。
- 一种极寒植物，可以提供低温绝缘材料。
- 一种能分解硫化物的微生物，可以成为工业净化技术的基础。

这就把探索与工业、科研、殖民连接起来了。

#### 4.4 引入生态干预，而不仅是采集和猎杀

玩家应该可以对生态进行多种干预：

| 行为     | 短期结果     | 长期结果     |
| ------ | -------- | -------- |
| 采集样本   | 获得科研素材   | 完成物种研究   |
| 捕猎     | 获取生物材料   | 可能破坏种群   |
| 驱逐掠食者  | 降低殖民地风险  | 草食动物大量繁殖 |
| 移植植物   | 改善局部环境   | 改变区域生态   |
| 引入外来物种 | 改变生物竞争关系 | 可能导致生态入侵 |
| 建立保护区  | 限制工业活动   | 增加生态科研价值 |
| 人工培育   | 获取稳定生物资源 | 形成新的生产体系 |

这样同一颗星球可以出现多种经营路线。

路线 A：工业化开发，牺牲部分自然生态，换取高产量。

路线 B：生态保护，建设自然保护区，获取高价值科研和生物材料。

路线 C：生态工程，将危险生态改造成适宜殖民的环境。

#### 4.7 将工业分成三个模拟层级

| 层级         | 主要内容                 | 模拟方式             |
| ---------- | -------------------- | ---------------- |
| L1：殖民地战略生产 | 当前建筑、生产配方、人口、电力、总库存  | 现有 colony 模拟继续保留 |
| L2：行星局部物流  | 传送带、管道、道路、仓储、电网、生产节点 | 网络图与吞吐量模拟        |
| L3：星际物流    | 货运发射、轨道仓储、运输舰、补给航线   | 航运任务与货物清单模拟      |

这一层级至关重要。

如果玩家仅仅把一座冶炼厂从建筑列表中拖进去，随后资源自动从全殖民地库存扣除，那么工业就没有真正的空间规划玩法。

反过来，如果每吨矿石都创建一个动态 3D 物体，又会使模拟开销失控。

因此建议：

逻辑上模拟资源流量，视觉上表现物流运动。

例如，1 小时生产 120 吨矿石，不需要真正创建 120 个矿石物体。

只要记录：

- 生产节点。
- 运输网络。
- 吞吐量。
- 输入缓冲。
- 输出缓冲。
- 消耗量。
- 运输延迟。

再由 Renderer 在适当位置显示运输车辆、物料光点和动态传送带即可。

#### 4.8 建立真正的行星物流网络

至少提供以下节点类型：

| 类型   | 设施                     | 职能      |
| ---- | ---------------------- | ------- |
| 采集   | 矿机、钻井、采样设施             | 资源产生    |
| 运输   | 传送带、管线、道路、货运轨道         | 资源移动    |
| 分流   | Splitter、Merger、Filter | 控制分配    |
| 缓冲   | 仓库、储罐、中转仓              | 暂存资源    |
| 加工   | 熔炉、化工厂、装配厂             | 改变材料    |
| 能源   | 发电站、储能站、配电节点           | 电力生产与传输 |
| 物流控制 | 调度塔、无人机站、运输站           | 网络管理    |
| 轨道出口 | 货运发射井、轨道货舱             | 对外运输    |

\*\*传送带（Conveyor）\*\*需要有：

- 输入、输出端口。
- 运输方向。
- 允许物料类型。
- 单位时间吞吐量。
- 最大坡度。
- 最大运输距离。
- 运输速度。
- 维护状态。

\*\*分流器（Splitter）\*\*需要有：

- 左右优先。
- 均分。
- 指定资源过滤。
- 溢出转运。
- 优先级端口。

这些机制会让玩家真正开始考虑生产布局。

#### 4.9 电力网络不能只是一个 `powerBalance` 数值

当前的 `powerBalance` 是很好的殖民地层电力模型，但行星工厂需要真正的局部能源网络。

建议加入：

```
发电站
  ↓
主干电缆
  ↓
区域配电节点
  ├── 矿业区
  ├── 冶炼区
  ├── 化工区
  ├── 居民区
  └── 防御区
```

每个区域维护：

- 当前电力供给。
- 当前电力需求。
- 最大供电能力。
- 能量缓冲。
- 线路损耗。
- 运行优先级。

例如，电力不足时：

1. 优先保证生命维持和医疗设施。
2. 其次保证安全防御。
3. 再保证核心工业。
4. 最后削减非必要设施。

玩家可以自定义优先级。

这样一次电力短缺就会演变为真实的管理问题，而不是简单弹出一条“能源不足”。

#### 4.10 生产网络要有瓶颈，而不应该是所有建筑自动高效工作

建议引入以下约束：

| 瓶颈    | 表现      | 玩家解决方式     |
| ----- | ------- | ---------- |
| 原料不足  | 生产停机    | 增加矿区或进口    |
| 运输不足  | 缓冲区堆满   | 加宽运输网络     |
| 电力不足  | 设备降速    | 新增电站或储能    |
| 水资源不足 | 化工和农业停机 | 建立循环水系统    |
| 人员不足  | 产能受限    | 招募、培训、自动化  |
| 仓储不足  | 产品无法输出  | 建立中转仓      |
| 天气破坏  | 线路故障    | 加固、维修、调整路线 |
| 敌对袭击  | 工厂停产    | 建立防御与巡逻系统  |

建议生产效率采用可追溯模型：

\\[ P\_{actual} = P\_{base} \times F\_{power} \times F\_{input} \times F\_{transport} \times F\_{staff} \times F\_{environment} \\]

其中每个系数都能在 UI 中明确展示。

这非常重要：玩家必须知道自己的工厂为什么不能达到理论产能，而不是只能猜测。

#### 4.11 建立可消耗的资源节点

当前矿脉标记能够支持 `HarvestTerrainOre`，但真正的矿业生产还需要矿藏量、开采速率和资源枯竭模型。

建议矿脉具有：

- 初始储量。
- 品位。
- 最大开采速率。
- 硬度。
- 深度。
- 开采污染。
- 剩余预计寿命。

同时加入地下钻探和深层资源：

- 地表露天矿。
- 浅层矿脉。
- 深层矿脉。
- 地下热液矿床。
- 古代工业残料。
- 异常矿物。

不同星球能够拥有不同资源开采路线。

- 跨星球生产调度。

蓝图应该支持参数化，例如：

“建立一套标准铁矿冶炼模块，需要铁矿资源评级至少 0.8，有 25 MW 的电力余量，并且存在距货运出口不超过 100m 的可用工业区域。”

这就把工业从手工摆放逐步升级为系统规划。

## 支柱三：动态极端气象与阶梯式威胁系统

关键：把环境从视觉装饰变成决策变量

当前主题定义已经拥有很多很好的基础，比如：

- `red_dust_storms`
- `whiteout_blizzards`
- `fumarole_gas_jets`
- `lava_eruption_cycles`
- `periodic_magnetic_pulses`
- `storm_wall_rotation`

但这些数据只有进入真实模拟，才能成为有意义的玩法。

#### 4.14 动态天气应该有生命周期

建议引入 Weather State Machine：

Clear Weather

正常环境

Warning

预警阶段：传感器、天空、广播提示灾害将至

Build-up

灾害发展：风速、温度、压力等指标逐渐异常

Peak Event

灾害峰值：区域影响达到最大

Recovery

恢复阶段：维修、清理、采集特殊产物

天气事件应该有：

- 持续时间。
- 作用区域。
- 强度。
- 移动方向。
- 预测准确度。
- 环境影响。
- 可规避程度。
- 特殊资源产出。

例如，一场硅晶风暴持续 12 游戏小时，其中心经过工业区。

玩家提前知道风暴将经过西部工业区，于是可以：

- 将采矿设备切换到防护模式。
- 暂停露天运输。
- 将货物转移至地下仓库。
- 派遣维护队加固电网。
- 在风暴结束后收集特殊硅晶沉积物。

这样天气就从扣血机制变成了一场需要提前规划的经营和生存事件。

#### 4.15 环境必须影响其他系统

| 天气类型 | 地表       | 工业        | 生态     | 社会     |
| ---- | -------- | --------- | ------ | ------ |
| 沙尘暴  | 能见度与移动下降 | 光伏衰减、运输磨损 | 植被受损   | 户外工作停摆 |
| 酸雨   | 防护层腐蚀    | 管线和建筑损坏   | 水体污染   | 居民患病   |
| 磁暴   | 通讯受干扰    | 电力与设备异常   | 动物迁徙异常 | 交通延误   |
| 白暴风雪 | 视野降低、低温  | 线路结冰      | 食物链变化  | 供热压力   |
| 熔岩喷发 | 地貌和路线改变  | 高温损坏设施    | 生境破坏   | 需要疏散   |
| 潮汐风暴 | 海岸淹没     | 浮台、管线受损   | 水生生物迁移 | 居民迁移   |

这才是一个真实的动态环境系统。

#### 4.16 建立行星威胁指数（Planetary Threat Index）

我建议将威胁分成两个主要来源。

第一类：人为活动引起的警戒度

例如：

- 采矿强度。
- 生态破坏。
- 工业污染。
- 古代设施激活。
- 强电磁信号。
- 武器试验。
- 高强度建筑施工。

第二类：星球原生威胁

例如：

- 原生虫群。
- 巨型掠食者。
- 古代自动防御系统。
- 特殊生态群体。
- 地质异常。
- 独立于玩家行为的周期性灾害。

人为警戒度可以采用一个可调的累计模型：

\\[ H_t = \operatorname{clamp} \left( H\_{t-1} +\sum_i w_i A_i -\lambda M_t, 0,100 \right) \\]

其中：

- \\(A_i\\)：不同扰动行为。
- \\(w_i\\)：各行为的威胁权重。
- \\(M_t\\)：隐蔽、屏蔽、安抚、净化等缓解行为。
- \\(\lambda\\)：缓解效率。

这里不要把所有活动都当成相同风险。

例如，普通钻井可能只产生很低的警戒度，而激活一个沉睡数百万年的外星巨构，应该导致非常明显的威胁增长。

#### 4.17 威胁必须具有真正的升级阶梯

| 等级 | 威胁状态        | 典型行为             | 玩家应对        |
| -- | ----------- | ---------------- | ----------- |
| 0  | Dormant     | 无活动              | 无需处理        |
| 1  | Detection   | 无人机侦察、异常信号       | 隐蔽或监测       |
| 2  | Harassment  | 少量巡逻单位           | 防护、驱逐       |
| 3  | Raid        | 成群袭击局部设施         | 组织防御        |
| 4  | Siege       | 对基地和工业网络实施持续攻击   | 建立防线、请求轨道支援 |
| 5  | Apex Threat | 巨型单位、巢穴核心或超级设施启动 | 大型战役、多阶段清除  |

关键不是每升一级刷出更多怪物。

应该让敌对势力拥有组织结构：

```
侦察单位
   ↓
威胁识别
   ↓
警戒网络
   ↓
局部袭扰
   ↓
集结与攻击
   ↓
核心设施 / 巢穴 / 指挥单位
```

玩家摧毁指挥节点后，敌方组织可能失去协同能力，而不是简单地所有敌人同时死亡。

对 Sentinels 和原生 Swarm 也应区分行为哲学：

- Sentinel：关注能源、技术设施、生态扰动与异常信号。
- Swarm：关注生物质、巢穴空间、繁殖区域和食物资源。
- 古代自动防御系统：关注特定遗迹区域与设施访问权限。
- 敌对文明：根据战略价值、领土和战争态势进行行动。

这样才会有不同的战术体验。

#### 4.18 环境与威胁的组合应该产生新的内容

例如：

玩家在硫雾沼泽大规模开采地下硫化物。

最初获得较高收益。

但是随着开采强度增加：

1. 地下压力与挥发物释放增加。
2. 沼泽气体浓度升高。
3. 某些原生生物迁离矿区。
4. 地下虫群被惊扰。
5. 工业传感器检测到异常活动。
6. 虫群逐步袭击采矿节点。
7. 玩家必须修筑高架防御设施或进入地下巢穴清除源头。

这是五大系统联动所产生的内容，不需要为每一步编写独立剧情任务。

## 支柱四：殖民聚落自治与社会微模拟

长期留存的重要基础

当前已经有：

- 人口数量。
- 人口阶层。
- 建筑岗位。
- 岗位优先级。
- 人口增长。
- 稳定度。
- 政策系统。

这是非常好的基础。

但现在殖民地还缺少一个重要特征：

#### 4.19 不建议给每个殖民者建立完整的高成本 AI

这会严重影响性能和存档。

建议采取三级社会模拟：

| 层级      | 表现方式                   | 模拟内容             |
| ------- | ---------------------- | ---------------- |
| L1：人口群体 | Worker、Scientist 等人口统计 | 人口、需求、满意度、工作效率   |
| L2：居民群组 | 某类居民的行为代理              | 通勤、工作、休息、消费      |
| L3：关键居民 | 具名角色实体                 | 总督、首席科学家、工程师、军官等 |

只有玩家正在访问的殖民地、重要事件和任务区域才需要表现更多活动实体。

而在远离玩家的殖民地，绝大部分居民仍然通过统计模拟推进。

这样既可以让玩家在地表看到生活中的居民，也不会让整个银河系的居民都进行每帧 AI 决策。

#### 4.20 建立居民需求体系

我建议将需求分成四个层次：

| 需求   | 影响          | 缺失后果      |
| ---- | ----------- | --------- |
| 生存需求 | 食物、水、氧气、住房  | 死亡、人口流失   |
| 安全需求 | 防御、医疗、环境保护  | 恐惧、工作效率下降 |
| 社会需求 | 公平、文化、休闲、教育 | 不满、冲突     |
| 发展需求 | 机会、职业、技术、收入 | 人才流失、科研下降 |

社会状态不应该只有一个 `stability` 数字。

建议至少增加：

- Morale：士气。
- Health：健康水平。
- Security：安全感。
- Equity：社会公平。
- Employment：就业水平。
- PoliticalTrust：对管理机构的信任。
- CulturalCohesion：社会凝聚力。

并允许不同人口群体拥有不同诉求。

例如：

- 工人关注劳动条件和工资。
- 科学家关注实验资源和科研自主权。
- 军事人员关注防御设施和战备。
- 商人关注贸易自由和市场空间。
- 原住民群体关注生态环境与文化保护。

#### 4.21 引入殖民地社会事件系统

真正有意思的事件应该由多个模拟状态组合而成。

| 事件     | 触发条件           | 玩家选择      | 后果          |
| ------ | -------------- | --------- | ----------- |
| 劳资纠纷   | 工业过度扩张、员工满意度下降 | 提高待遇或强制劳动 | 成本、产能、稳定度变化 |
| 疫情     | 新生物、卫生不足       | 封锁、研究、治疗  | 人口与生物技术变化   |
| 走私网络   | 市场活跃、管理薄弱      | 监管或默许     | 财政、腐败、贸易变化  |
| 科研伦理争议 | 生物实验规模增加       | 限制实验或开放研究 | 科研效率、社会信任   |
| 生态保护抗议 | 工业污染、保护区被破坏    | 让步或镇压     | 社会稳定、产业损失   |
| 工程师罢工  | 维修不足、福利下降      | 妥协或更换管理层  | 工业产能变化      |

关键是事件必须有前因、选择、结果和历史记录。

而且后续事件应该能够引用过去的选择。

例如，殖民地曾经强制镇压工人罢工，十年后可能出现工人地下组织、工业破坏或大规模迁移。

#### 4.22 增加殖民地治理方向

政策系统应该能够影响真实的世界运行结果。

建议增加六种治理方向：

1. 工业优先。
2. 科研优先。
3. 军事管制。
4. 生态保护。
5. 商业自由。
6. 社会福利。

这些政策不应该只有固定加成。

例如生态保护政策可以：

- 限制部分矿区开采量。
- 提高生态恢复速度。
- 降低物种灭绝风险。
- 吸引科研人员。
- 提高特殊生物资源价值。

军事管制政策则可能：

- 提高安全与防御效率。
- 增加军事人员比例。
- 降低部分商业自由度。
- 提高行政成本。
- 在长期战争中增强社会动员能力。

#### 4.23 引入殖民地类型

不同殖民地应该拥有不同的运营逻辑。

| 类型                  | 主要设施         | 主要目标      |
| ------------------- | ------------ | --------- |
| Scientific Outpost  | 实验室、扫描站、样本库  | 科研突破      |
| Mining Colony       | 矿区、冶炼、运输     | 资源获取      |
| Industrial World    | 大型工厂、电网、物流枢纽 | 工业生产      |
| Agricultural World  | 农场、生物实验室、水循环 | 食物和生物资源   |
| Military Fortress   | 离子炮、雷达、军营    | 防御与军事投射   |
| Trade Port          | 仓储、货运发射、市场   | 物流与贸易     |
| Ecological Preserve | 生态保护设施、基因库   | 生物保存与生态研究 |

这就让殖民决策本身成为一种战略游戏。

#### 4.24 轨道火力支援（Orbital Fire Support）

建议至少提供五种支援方式：

| 支援方式               | 效果           | 限制          |
| ------------------ | ------------ | ----------- |
| Orbital Laser      | 精确攻击地表目标     | 需要目标定位，持续供能 |
| Kinetic Strike     | 大范围动能打击      | 高风险、冷却时间长   |
| Electronic Warfare | 干扰敌方设备、雷达与通讯 | 需要轨道电子战舰    |
| Drone Deployment   | 投放侦察或攻击无人机   | 受局部防御和天气影响  |
| Supply Drop        | 空投医疗、弹药、工程组件 | 需要稳定空投窗口    |

这里需要特别注意：不能让轨道火力变成无限次免费按钮。

每次呼叫都应该有：

- 轨道舰队位置。
- 武器冷却。
- 能源或弹药消耗。
- 目标定位质量。
- 大气条件。
- 防空威胁。
- 友军伤害风险。
- 战术通信与请求延迟。

例如，磁暴期间，轨道舰队难以稳定锁定地表目标。玩家必须先恢复地面雷达站，才能获得高精度火力支援。

这会自然形成新的地表任务目标。

#### 4.25 行星级防空与轨道反制

这是我认为值得做成特色玩法的部分。

建议新增：

- Planetary Ion Battery。
- Orbital Tracking Radar。
- Planetary Shield Generator。
- Anti-Ship Missile Silo。
- Long-range Sensor Array。
- Orbital Interception Network。

它们不能只是攻击力更高的建筑。

应当要求一套完整系统：

```
地面雷达
   ↓
轨道目标识别
   ↓
防空指挥中心
   ↓
能源与弹药供应
   ↓
离子炮 / 导弹阵列
   ↓
轨道目标拦截
```

如果雷达被摧毁，即使离子炮仍然存在，也无法有效攻击远距离高速目标。

如果电力网络瘫痪，则防空能力下降。

如果导弹供应链中断，防空阵列就可能逐渐失去战斗力。

这让工业、基础设施和军事防御真正融为一体。

#### 4.26 建立双向空地战略影响

不仅轨道能够影响地表，地表也必须能够影响轨道。

| 地表行为      | 轨道后果                 |
| --------- | -------------------- |
| 建造大型雷达    | 提高己方舰队侦察与探测能力        |
| 建立防空设施    | 降低敌方轨道轰炸效果           |
| 激活古代中继站   | 解锁长距离战略通信            |
| 建立货运发射中心  | 增加轨道补给能力             |
| 摧毁敌方地面能源站 | 削弱敌方轨道护盾或设施运行        |
| 占领重要高地    | 提高局部轨道火力校正精度         |
| 开展大规模地表采矿 | 提高星球战略资源价值，同时增加被侦察概率 |

最终形成：

轨道舰队决定行星的战略环境，行星设施决定舰队的持续作战能力。

这才是完整的天地一体化。

### 五、五大支柱之间必须有统一的系统联动

我认为这部分比五个支柱各自增加多少功能还重要。

不能把生态、工业、天气、殖民地和军事做成五个相互独立的模块。

它们应该共享相同的资源、地理位置、事件历史和世界状态。

#### 5.1 核心联动矩阵

| 系统   | 生态      | 工业      | 天气     | 社会       | 空地战略       |
| ---- | ------- | ------- | ------ | -------- | ---------- |
| 生态   | 物种相互影响  | 提供生物材料  | 天气改变种群 | 生态保护引发政策 | 特殊生物影响军用材料 |
| 工业   | 污染、生态培育 | 物流和生产   | 灾害造成停产 | 劳动和资源需求  | 支持舰队与防御    |
| 天气   | 改变生境    | 破坏设备    | 天气循环   | 疏散和医疗    | 影响轨道支援     |

初期：先遣科考

玩家进入星系后发现这颗行星存在大量特殊挥发物与未知生物信号。

轨道扫描发现：

- 高浓度硫化物区域。
- 异常地下热源。
- 大型失联研究设施。
- 生物群落活动异常。

玩家派出科考队。

调查过程中发现一种能够耐受高浓度毒气的微生物。

中期：科技开发

玩家取得微生物样本并进行实验。

经过多个实验阶段，解锁：

- 新型空气过滤器。
- 耐腐蚀涂层。
- 生物质净化设备。

产业建设

玩家决定建立化工殖民地。

建设：

- 硫化物采集站。
- 化工处理厂。
- 耐腐蚀管道。
- 生物净化设施。
- 独立储能网络。

随后建立货运发射井，将特殊材料输送到轨道船坞。

环境反噬

过度开采导致局部硫化气体浓度增加。

天气系统开始产生酸雨事件。

社会问题

殖民地居民因长期暴露于化学污染环境，出现健康问题。

科研人员要求限制采矿。

工业集团则希望维持高产量。

玩家需要选择：

- 继续工业扩张。
- 限制污染并建设净化设施。
- 将部分工业转移至轨道。
- 划定生态保护区。

军事危机

玩家激活古代地下研究站后，发现其防御网络仍在工作。

古代 Sentinel 设施重新启动，开始攻击周围能源设施。

玩家可以：

- 请求轨道精确打击。
- 派遣地表小队进入地下控制中心。
- 切断供能。
- 修复古代控制节点，使其变成自己的防御网络。

最终，这颗行星可能成为：

- 高污染高产量化工世界。
- 高科研价值生态研究世界。
- 具备特殊防御能力的军事基地。
- 生态与工业平衡的高宜居殖民地。

同一个种子、同一个世界，可以因为玩家决策形成不同的发展轨迹。

这就是应该追求的内容深度。

### 六、程序化内容生成：从「程序化地形」升级为「程序化世界内容」

这是全局方案最重要的技术方向之一。

目前已经有：

- `derivePlanetSeeds()`
- `planetThemes.js`
- `terrainField.js`
- `missionSiteFactory.js`
- `planetPOI.js`

这些是良好的基础。

但未来程序化生成不能只解决地形、主题、POI 的位置，还必须解决世界中有哪些活动、相互关系如何、玩家会遇到什么问题。

#### 6.1 建立行星内容生成流水线

建议固定为以下顺序：

```
1. 行星物理参数
       ↓
2. 行星主题选择
       ↓
3. Primary / Secondary Gameplay Role
       ↓
4. 宏观地貌与 Biome Patches
       ↓
5. 生态与资源分布
       ↓
6. 历史文明与遗迹生成
       ↓
7. 任务核心与外围活动生成
       ↓
8. 殖民与工业适用性评估
       ↓
9. 威胁与环境机制生成
       ↓
10. 运行内容质量验证
       ↓
11. 形成可持久化 Planet Profile
```

我建议在现有主题之外增加 `Planet Gameplay Role Registry`。

例如：

```
{
  primaryRole: "ecology_research",
  secondaryRoles: [
    "industrial_chemistry",
    "archaeology"
  ],

  signatureMechanism: "acid_bio_chemistry",

  resourceFocus: [
    "biomass",
    "reagents",
    "rareEarth"
  ],

  ecologyProfile: "sulfur_swamp_ecology",
  archaeologyProfile: "lost_research_network",

  threatProfile: "native_swarm",

  strategicValue: "industrial_technology"
}
```

这样程序化生成出来的不是一颗“主题为硫雾沼泽”的星球，而是一颗有明确用途、探索方向和长期目标的硫雾沼泽星球。

#### 6.2 建立内容组合语法，而不是无限增加主题 ID

18 个主题不应该永远继续增加到 100 个。

更好的方式是引入多层组合：

| 维度   | 组合示例                     |
| ---- | ------------------------ |
| 地貌   | 平原、峡谷、盆地、山脉、裂谷、冰原        |
| 生境   | 潮湿森林、浅海、深海、岩洞、湿地、荒漠      |
| 环境修饰 | 酸雾、磁暴、低重力、极夜、强潮汐         |
| 生态类型 | 掠食型、共生型、菌类型、能量型          |
| 历史类型 | 失联前哨、古代巨构、坠毁舰队、战争遗址      |
| 工业机会 | 稀有矿物、化工、地热、农业、能源         |
| 威胁类型 | Sentinel、Swarm、海洋巨兽、地质异常 |

通过这些组合，一颗星球可以有丰富的变化，但仍然遵守明确的逻辑。

#### 6.3 让生成过程具备内容质量验证

我建议每颗星球生成后都执行一组内容质量检查：

- 是否有明确的主要玩法身份？
- 是否存在至少两个有意义的活动入口？
- 主要 POI 是否能找到？
- 主要内容是否存在可完成的交互链？
- 是否存在至少一种环境或生态机制？
- 资源是否能够实际进入工业链？
- 高风险区域是否具有对应的收益或探索价值？
- 是否存在合理的安全路径？
- 是否存在后续回访理由？
- 生成结果是否与主题矛盾？

不要把随机生成成功等同于内容生成成功。

#### 7.3 确定性随机数需要统一规范

这里发现了一个委托书与实际代码之间值得明确裁定的地方。

委托书 L103 提到 `splitmix32/mulberry32`，而当前仓库中：

- `src/core/rng.js` 使用 xoshiro128\*\* 世界随机数状态。
- `src/domain/ground/planetSeeds.js` 通过 `hash32` 对 `world.seed` 与 `planet.id` 派生独立子种子。
- 已有地貌、主题、POI 等独立子流。

我的建议是：

不要为了符合旧文字描述而替换当前已经稳定的随机数内核。

应该冻结当前实现口径，将新子流纳入同一确定性规则：

```
worldSeed
   └── planetSeed(planetId)
        ├── themeSeed
        ├── macroTerrainSeed
        ├── biomeSeed
        ├── decorationSeed
        ├── missionSiteSeed
        ├── poiSeed
        ├── ecologySeed
        ├── weatherSeed
        ├── archaeologySeed
        ├── industrySeed
        ├── settlementSeed
        └── threatSeed
```

这些子流应当相互独立，且不得消费主 `world.rng`。

加入 `generatorVersion`，使未来算法升级时能够保留旧存档的世界语义。

#### 7.4 存档和内存预算

这是开发中必须重点保护的部分。

委托书要求每颗星球的持久化增量严格小于等于 50KB，并且：

- `commandBus.deepClone(world)` 单步不超过 0.5ms。
- 新增状态必须是纯数据。
- 不允许把运行时重型对象和闭包放进存档树。

  15_无垠边疆超长线演化开发调研任务委托书.md



我建议把单星球新增状态的预算预先切分：

| 数据类型         | 预算    |
| ------------ | ----- |
| 生态斑块与物种状态    | 6 KB  |
| POI 与考古进度    | 8 KB  |
| 天气与灾害状态      | 2 KB  |
| 工业网络拓扑与缓冲数据  | 12 KB |
| 殖民社会模拟       | 5 KB  |
| 轨道货运和任务状态    | 4 KB  |
| 地形、设施与玩家改造差异 | 10 KB |
| 安全余量         | 3 KB  |
| 合计           | 50 KB |

这些是新增系统的工程预算分配，最终还需要根据真实序列化大小测量。

具体实现必须：

- 使用紧凑索引，减少重复字符串。
- 使用稀疏数组，只保存玩家改变过的状态。
- 不保存每只生物、每个传送带物品的完整对象。
- 不保存可重建的网格、缓冲区、Shader 和运行时缓存。
- 采用压缩的地形编辑或物流拓扑表示。
- 对历史、日志和临时任务状态设置容量上限。

尤其要注意，生态种群应该存储数量和密度，而不是把整片森林的每一株植物塞进存档。

#### 7.5 时间分片和离屏模拟

当前 1 tick = 1 游戏小时，这个时钟已经适合做统一的长线模拟。[clock.js](https://github.com/zhaotong96/void-frontier-age-of-stars/blob/main/src/core/clock.js?utm_source=chatgpt.com)。

我建议：

| 频率        | 主要系统                   |
| --------- | ---------------------- |
| Hourly    | 工业生产、运输、主动天气推进、战斗、关键任务 |
| Daily     | 人口、生态种群、资源损耗、社会状态、威胁衰减 |
| Monthly   | 大型产业统计、生态趋势、殖民发展、市场变化  |
| Seasonal  | 生物迁徙、繁殖周期、极端季节、长期环境变化  |
| On Demand | 进入星球时的区域状态重建、视图数据和渲染缓存 |

离屏星球不应该因为玩家没有访问而停止世界演化。

但是也不应该对 608 颗星球中的每一只生物、每一条传送带执行每小时 AI。

建议采用：

活动区域精细模拟 + 非活动区域聚合结算 + 延迟补算。

例如玩家离开星球时，保存各个系统的最后更新时间。下次进入时，按照经过的游戏时间，批量推演生态、天气和工业累计变化。

#### 7.6 WebGL 渲染预算需要提前处理一个潜在冲突

委托书要求单屏 Draw Call 不超过 50。

但当前 `PlanetSurfaceScene.js` 对地形绘制的说明是每个可见 Chunk 独立 Draw Call，64 个 Chunk 的设计上限可能达到 64 次。

这与 50 次预算存在潜在冲突。

建议后续将以下要求写入门禁：

- 地形 Chunk 使用视锥裁剪。
- 使用 LOD 与合并网格减少绘制次数。
- 植被和生物必须使用实例化渲染。
- 同类建筑统一批处理。
- 粒子统一批处理。
- 动态物体不能按数量线性增加 Draw Call。
- 最坏视角、最大建筑密度和最大生态密度下实测 Draw Call。

不要只在空旷地形中进行性能验收。

### 八、分阶段研发路线：v0.2～v1.0

我不建议马上让多个 Agent 同时开始五大支柱的完整施工。

最容易出现的情况是：每个 Agent 都交付了一个功能模块，但这些模块之间没有完整的数据契约、事件契约和 Gameplay 连接，最终又形成一堆孤岛。

更合理的方案是先建立一个统一的行星活动内核，再逐步加入系统。

下面是一套建议按 12～18 个月演化的路线，具体工期应由每阶段实际验证后的工作量决定。

#### 8.1 v0.2：Planetary Activity Kernel

4. 多阶段 POI 状态机。
5. 地表活动追踪。
6. 地表行动结果持久化。
7. 多次登陆状态一致性。
8. 探索结果进入科研、资源和殖民系统。

- 生物材料生产。

验收要求：

玩家引发的生态扰动，必须能够在之后重新进入地表时观察到变化，并且能够通过游戏机制解释变化原因。

#### 8.3 v0.4：Ancient Civilizations

首批建议设计三个遗迹体系：

| 遗迹体系    | 主题                      | 玩法特征           |
| ------- | ----------------------- | -------------- |
| 星门遗址    | `ancient_megastructure` | 解密、能源恢复、空间航线科技 |
| 地下海洋研究站 | `abyssal_ocean`         | 深潜、压力、设备恢复     |
| 极夜观测阵列  | `dry_night_polar`       | 天文信号、磁场数据、古代通讯 |

验收要求：

每个大型遗迹具有至少三个实质性互动阶段和一个有后果的最终决策。

#### 8.4 v0.5：Dynamic Planetary Environment

首批天气原型：

- 沙尘暴。
- 酸雨。
- 磁暴。
- 暴风雪。

每种天气至少要具有预警、发生、峰值、恢复四个状态。

验收时不仅看画面效果，还要验证天气能够影响工业、生态、移动和殖民地。

#### 8.5 v0.6：Planetary Industry Network

第一条生产链建议选用现有资源体系中的真实配方：

```
    Smelter
       ↓
     Alloy
       ↓
   Assembler
       ↓
   Composite
       ↓
  Orbital Shipyard
```

需要验证：

- 矿石采掘。
- 输送。
- 分流。
- 加工。
- 电力。
- 仓储。
- 产能瓶颈。
- 输出与物流。
- 轨道交付。

先把一条链真正做深，再推广更多配方。

#### 8.6 v0.7：Living Settlements

优先加入：

- 居民需求。
- 工作与岗位。
- 设施通勤。
- 劳动条件。
- 社会事件。
- 聚落治理。
- 政策后果。
- 灾后重建。

这阶段不必让所有 NPC 都具备完整行为树。

应先实现群组模拟与关键居民。

#### 8.7 v0.8：Orbital-Surface Warfare

优先建立三条完整链路：

1. 轨道舰队向地表请求火力。
2. 地表防空设施拦截敌对轨道目标。
3. 地表货运发射系统向轨道船坞提供物资。

这三条链路闭环之后，再扩展更多空地支援类型。

#### 8.8 v0.9～v1.0：内容扩展与世界平衡

这一阶段才应该大规模扩展 608 颗星球的玩法身份。

主要工作：

- 统一 18 主题对应的生态、天气、工业和任务内容。
- 扩展 8 种天体类别的特殊交互。
- 建立特殊文明和文明历史。
- 丰富事件和任务组合。
- 建立标准化星球内容验证工具。
- 完成大量随机种子下的自动化长期模拟。
- 验证不同玩家发展路线的平衡性。

### 九、每颗星球的内容验收标准：建立 Planetary Content Depth Index

这是我强烈建议引入的一项项目指标。

目前项目很容易用“地图生成正常”“主题渲染正常”“POI 存在”来判断一颗星球已经完成。

但是这些无法说明玩家是否真的有内容可玩。

我建议建立一个行星内容深度评分：

Planetary Content Depth Index（PCDI）

建议评分体系，满分 100。它是设计管理指标，不是自动取代实际玩家测试的评分器。

| 维度                 | 权重 | 评估内容             |
| ------------------ | -- | ---------------- |
| Exploration Depth  | 15 | 扫描、发现、追踪和调查是否有层次 |
| Activity Variety   | 20 | 是否有多种有意义的玩家行动    |
| System Interaction | 20 | 不同玩法系统是否互相影响     |
| World Persistence  | 15 | 玩家行为是否永久改变星球     |
| Strategic Value    | 10 | 是否影响科研、工业、贸易和军事  |
| Replay Value       | 10 | 是否值得再次访问         |
| Theme Uniqueness   | 10 | 是否具有无法简单复制的主题玩法  |

建议验收标准：

| 星球等级   | PCDI 目标 |
| ------ | ------- |
| S 旗舰世界 | 85～100  |
| A 特色世界 | 75～84   |
| B 功能世界 | 65～74   |
| C 边疆世界 | 不低于55   |

一个 3D 地形非常漂亮，但玩家只能够扫描一个矿点、领取一次奖励的星球，应该被判定为低内容深度。

### 十、研发执行策略：先做垂直切片，再规模化生产

这部分决定 Agent 能否长期稳定地完成项目。

我建议把未来研发任务分成四个独立工作流，但它们必须共用一份接口规范。

| 工作流                   | 负责人类型           | 核心成果                         |
| --------------------- | --------------- | ---------------------------- |
| A：Planet Simulation   | 模拟与领域系统工程 Agent | 生态、天气、威胁、社会状态机               |
| B：Gameplay & Content  | 游戏系统与关卡设计 Agent | POI、考古、任务、物种和内容模板            |
| C：Industry & Strategy | 经济与战略系统 Agent   | 工业网络、能源、物流、空地支援              |
| D：Integration & QA    | 架构集成与测试 Agent   | CommandBus、Snapshot、存档、浏览器验收 |

但是要严格控制并行关系。

在 `Planetary Activity Kernel` 完成前，不应让所有工作流同时修改 World Schema。

#### 10.1 第一批技术预研任务

我建议优先进行六项小规模原型验证：

| 原型                        | 需要验证的问题           | 最小实验               |
| ------------------------- | ----------------- | ------------------ |
| Ecology Prototype         | 生态模拟是否足够轻量        | 5 个物种、3 个区域、10 年推进 |
| Industry Prototype        | 图网络是否能表达真实物流      | 50 个节点、100 条边、资源流量 |
| Weather Prototype         | 天气是否能对工业和地表造成因果影响 | 4 类天气、2 个殖民地       |
| Archaeology Prototype     | 考古是否具有真正的阶段性      | 一座 3 节点、5 阶段遗址     |
| Social Prototype          | 群组模拟能否产生社会事件      | 3 类群体、5 种需求        |
| Orbital Support Prototype | 轨道与地表是否能真实互相影响    | 一艘轨道舰、一套地面离子炮      |

原型阶段不追求 UI 华丽，也不追求内容数量。

重点是确认：

- 数据模型可行。
- 确定性可靠。
- 状态可以持久化。
- 性能符合预算。
- 能够通过真实命令产生玩家可见结果。

#### 10.2 推荐的 Agent 交付规则

每一项研发任务都应该明确以下内容：

1. 当前已有实现和文件位置。
2. 本次需要新增的领域能力。
3. 不允许修改的现有接口和不变量。
4. 新增 World 字段及迁移方式。
5. 命令、事件和快照契约。
6. 玩家可以执行的操作。
7. 预期世界状态变化。
8. 自动化测试。
9. 真实浏览器验收。
10. 对已有功能的回归影响。

最重要的是第 7 点。

只实现一个 UI 面板、一个配置项、一个数据结构，不应该视为游戏玩法完成。

必须能够从玩家操作一路追踪到 World 状态变化、存档、事件回写和后续系统影响。

### 十一、需要特别避免的六种研发误区

| 误区              | 为什么危险     | 正确做法         |
| --------------- | --------- | ------------ |
| 无止境增加星球         | 内容密度没有改善  | 先完善旗舰星球      |
| 无止境增加物种         | 只是扩大图鉴    | 建立生态关系和研究闭环  |
| 无止境增加建筑         | 仍然只是建筑列表  | 建立生产网络和物流瓶颈  |
| 无止境增加任务         | 容易变成重复模板  | 让任务结果改变世界    |
| 每个 NPC 都运行完整 AI | 模拟性能和存档失控 | 群组模拟、关键居民实体化 |
| 过早增加大型剧情        | 剧情与系统割裂   | 先让世界模拟能够产生事件 |

还需要增加三个容易被忽视的设计要求：

第一，世界不能永远惩罚玩家。

如果每次采矿都会引发袭击，每次天气变化都会摧毁建筑，每次工业扩张都会导致社会危机，那么玩家最终会厌倦。

应当让玩家能够通过技术、规划、政策和设施建设，逐渐降低风险。

第二，奖励必须具有真正的战略价值。

不能每个 POI 最终只奖励 10 个科研点或 50 单位矿石。

某些发现应该解锁其他星球的特殊产业、舰船模块、生态技术、特殊建筑和文明级技术路线。

第三，建设必须有空间意义。

如果一个建筑放在地图任何地方都完全一样，地形、道路、坡度、海岸和资源位置就失去了设计价值。

这是《无垠边疆》已经具备三角化连续地形之后，最应该继续发挥的优势。

### 十二、标杆游戏的真正经验：内容来自新系统及其相互连接，而不只是更新数量

《无人深空》值得研究的核心，是其更新逐渐为玩家引入新的行动方式、目标和系统关系，而不只是继续改变行星外观。

### 十四、最终裁定与实际执行优先级

我认为这次不应该把任务委托书理解成“再开发五个大型功能”。

更准确的理解应该是：

将已有行星技术底座升级为完整、持续运行、玩家可干预、可产生涌现内容的行星世界模拟系统。

我的最终优先级如下：

| 优先级 | 任务                        | 关键原因                 |
| --- | ------------------------- | -------------------- |
| P0  | Planetary Activity Kernel | 没有统一活动内核，后续功能仍然会成为孤岛 |
| P0  | POI 多阶段活动与世界记忆            | 直接解决探索一次性问题          |
| P1  | 生态与科考                     | 最容易产生差异化探索内容         |
| P1  | 多阶段考古                     | 提供独特的长期目标和文明叙事       |
| P1  | 动态天气与威胁                   | 使行星拥有持续的生存与战术变化      |
| P1  | 工业空间物流                    | 让地表建造真正成为经营玩法        |
| P2  | 社会自治                      | 增加长期殖民管理和事件涌现        |
| P2  | 空地战略                      | 将微观地表与宏观银河战略完全打通     |
| P2  | 608 颗星球内容扩展               | 在前述系统成熟后规模化推广        |

我认为 v0.2 最应该解决的不是增加 100 种物种、50 座遗迹或者 20 座工厂，而是完成三颗真正有内容的旗舰星球。

它们应该分别证明：

- 一颗星球能够因生态而值得研究。
- 一颗星球能够因历史和考古而值得反复探索。
- 一颗星球能够因工业、气象和威胁而值得长期经营。

这三颗星球的内容系统一旦跑通，才有资格向全部主题推广。

最终，我希望玩家在《无垠边疆》中产生这样的感受：

> 我登陆这颗星球时，它只是一个陌生的异星世界。
>
> 我发现了它的生命、资源和古代历史。
>
> 我建立了设施，改变了环境，创造了工业，治理了居民。
>
> 我经历了灾害、生态变化、敌对势力和文明冲突。
>
> 数十个游戏年之后，我重新降落到这颗星球，看到的已经不是最初那个世界。
>
> 它有我的基地、我的产业、我的研究成果、我的历史，也有我过去决策所留下的代价。

这才是我认为《VOID FRONTIER: AGE OF STARS》应该达到的超长线目标：不是生成 608 颗可以访问的星球，而是生成 608 个有机会被玩家赋予不同命运的世界。
