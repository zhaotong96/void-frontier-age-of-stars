## 1. 规范概述与战役验收定位

### 1.1 核心问题与战役黄金路径（The Golden Path）
在 4X 太空战略游戏中，孤立验证某一个子系统（如单次伤害计算、单个矿物开采）不能代表游戏能够正常通关。一款游戏只有在其**核心游玩主线（战役黄金路径）**从开局到终局能完整自洽地推进完毕，才能宣告达到发版与验收水准。

过往测试中，由于缺乏长链路端到端自动化，经常出现：
* 前期建造顺畅，但发展到科技中期时因科技树依赖关系错位导致科技无法继续研究；
* 舰队遭遇深空海盗时，战术结算与残骸回收逻辑产生未捕获异常，导致战役中断；
* 建造第二殖民地或部署轨道质量投射器时，跨行星物流链路无法形成闭环；
* 触发终局胜利事件时，编年史（`ChronicleView`）或成就结算未能正确触发。

本施工方案制定了针对标准战役 **CAMPAIGN-01「边疆回声」** 的四大战役里程碑端到端自动化验收规约，确保主线流程 100% 真实跑通。

## 3. 四大里程碑详细验收契约与断言门禁

### 3.1 里程碑 1：拓荒序章（Pioneer Genesis）
* **前置条件**：以种子 `24601` 启动 [`createStarterCampaign`](file:///c:/Users/[REDACTED]/My%20Drive/work/void-frontier-age-of-stars/src/devtools/scenarioFactory.js)。
* **自动化行为链**：
  1. 向母星殖民地下发建筑建造指令：`BuildOnColony`（矿物精炼厂 + 太阳能阵列）。
  2. 启动科技研发：`StartResearch`（`tech_basic_energy`）。
  3. 时钟推进 30 个游戏日（`advanceTicks(world, 720)`）。
* **硬性断言**：
  * `world.entities.colonies[homeColonyId].buildings` 包含新建建筑且处于 `active` 状态。
  * `world.entities.factions[playerFactionId].researchedTechs` 包含 `tech_basic_energy`。
  * 母星资源账本能量日增量 $> 0$，人口满意度 $> 75\%$。

### 3.2 里程碑 2：星际开拓与深空战役（Expedition & Deep Space Combat）
* **自动化行为链**：
  1. 母星船坞下达建造指令：`ShipyardBuild`（`hull_corvette` 护卫舰 $\times 2$）。
  2. 组装远征舰队：`AssembleFleet`。
  3. 下达航路移动指令：`OrderFleetMove` 跳跃至邻近星系（如 `sys_proxima`）。
  4. 触发深空海盗遭遇战：进入战术结算阶段（[`engagement.js`](file:///c:/Users/[REDACTED]/My%20Drive/work/void-frontier-age-of-stars/src/domain/combat/engagement.js)）。
  5. 经过多轮护盾/装甲分层伤害计算，摧毁敌舰并打捞残骸。
* **硬性断言**：
  * 玩家舰队到达目标星系，且舰队生存战力 $> 0$。
  * 战斗状态记录中 `outcome === 'victory'`。
  * 账本收割到战斗掉落合金与声望增量。

### 3.3 里程碑 3：天地物流与第二殖民地（Logistics & Expansion）
* **自动化行为链**：
  1. 地表建造电磁质量投射器：`CatapultFeed`。
  2. 建造深空殖民船，跃迁至已探明宜居行星。
  3. 建立第二前哨殖民地：`FoundOutpost`。
  4. 建立母星与第二殖民地之间的常规运输路线（[`colonyTrade.js`](file:///c:/Users/[REDACTED]/My%20Drive/work/void-frontier-age-of-stars/src/domain/economy/colonyTrade.js)）。
* **硬性断言**：
  * `Object.keys(world.entities.colonies).length === 2`。
  * 跨星系物资调拨每季度成功交付一次，无货物丢失。

### 3.4 里程碑 4：巨构工程与星海霸权（Megastructure & Victory）
* **自动化行为链**：
  1. 推进模拟时钟至巨构科技就绪。
  2. 启动轨道巨构建造工程（轨道要塞 / 戴森云天线）。
  3. 达成战役胜利条件（[`victory.js`](file:///c:/Users/[REDACTED]/My%20Drive/work/void-frontier-age-of-stars/src/domain/victory/victory.js)）。
  4. 自动跳转至胜利结算面板，验证编年史视图数据完整性（[`ChronicleView.js`](file:///c:/Users/[REDACTED]/My%20Drive/work/void-frontier-age-of-stars/src/ui/screens/ChronicleView.js)）。
* **硬性断言**：
  * `world.victoryState.achieved === true`。
  * `world.victoryState.type` 匹配预期胜利分支（如科技霸权 / 领土扩张）。
  * 编年史时间轴条目数 $\ge 4$，完整记录从开局到胜利的全部重大历史事件。

### 4.1 `CampaignMilestoneRunner.js` 接口契约规范

```javascript
/**
 * tests/e2e/CampaignMilestoneRunner.js
 * 战役黄金路径端到端自动化验收调度器
 */
export class CampaignMilestoneRunner {
  constructor(app, options = {}) {
    this.app = app;
    this.options = Object.assign({
      seed: 24601,
      timeoutMs: 60000,
      logMilestones: true
    }, options);
  }

  /** 按序执行四大里程碑验收并返回审计报告 */
  async runCampaignAcceptance() {
    const report = {
      campaign: 'CAMPAIGN-01 边疆回声',
      startTime: Date.now(),
      milestones: [],
      passed: false
    };

    try {
      // 1. 拓荒序章
      const m1 = await new Milestone1Genesis(this.app).execute();
      report.milestones.push(m1);

      // 2. 星际开拓与深空战役
      const m2 = await new Milestone2Combat(this.app).execute();
      report.milestones.push(m2);

      // 3. 天地物流与第二殖民地
      const m3 = await new Milestone3Logistics(this.app).execute();
      report.milestones.push(m3);

      // 4. 巨构工程与星海霸权
      const m4 = await new Milestone4Victory(this.app).execute();
      report.milestones.push(m4);

      report.passed = report.milestones.every(m => m.success === true);
    } catch (err) {
      report.passed = false;
      report.fatalError = { message: err.message, stack: err.stack };
      throw err;
    } finally {
      report.durationMs = Date.now() - report.startTime;
    }

    return report;
  }
}
```

## 5. 验收门禁与阻断指标

1. **真实链路全通**：四大里程碑必须 100% 连续通过，严禁通过直接修改世界状态属性来“跳关”。
2. **时限约束**：在 Node 模拟环境下，四大里程碑全流程推进必须在 **30 秒** 内圆满收官。
3. **编年史闭环**：战役结束后，编年史数据结构必须能被 `ChronicleView` 正确反序列化并渲染，无格式解析异常。

> [!IMPORTANT]
> 战役执行过程中涉及大量命令调度与异步事件监听，所有执行器必须统一使用 `await waitForEvent(eventBus, 'expected_event', timeout)` 模式，严禁使用固定的 `setTimeout` 硬等待，以防在低性能 CI 机器上产生竞态超时假死。
