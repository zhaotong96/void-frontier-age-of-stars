### 三、 深度源码取证：遗留缺陷 F-10 主体解构与 3 项新发现残余微瑕

专家组对 [test_review.md]([REDACTED]) 中挂起待修的 **F-10 主体（太空战术战斗集成停局）** 进行了全链路数学仿真与源码穿透，确认其并非单一 Bug，而是由 **4 处源码机制缺陷叠加而成的复合死锁簇**，同时定位了 F-07 与 F-09 中残余的 **3 处边界微瑕**。

#### 1. F-10 主体（太空战术战斗集成停局：为何 `dmgA` 精确卡在 `734.4` 且坐标永久冻结？）

* **病灶一：交战配对无视舰队武装能力，把双无武装科考/殖民舰队拉入无超时的 `annihilate` 死斗（[engagement.js]([REDACTED]) 第 23–40、86 行 & [FactionAI.js]([REDACTED]) 第 259–449 行）**
* 在 [engagement.js]([REDACTED]) 第 38–39 行中，只要同一星系内两支舰队所属阵营处于战争状态（`warActiveBetween` 为 `true`），即使双方均为 `stance === 'hold'` 且均为**零武器的非战斗舰队**（`hull_science` 科考船或 `hull_supply` 殖民补给船），也会无条件创建 `endCondition: { kind: 'annihilate' }`（第 86 行，无 `timeoutSeconds`）的死斗。
* 在 [FactionAI.js]([REDACTED]) 中，`aiMilitary`（第 389–449 行）未实现跨星系派遣战斗舰队进攻的逻辑，AI 唯一跨星系移动的是零武器的 `science` 与 `colony` 舰队；且每个文明初始舰队按 `science` ➔ `colony` ➔ `combat` 顺序创建，导致玩家远征舰队进入 AI 母星系时，在第 37 行 `if (inBattle(world, A.id) || inBattle(world, B.id)) continue;` 抢占规则下，优先与排在最前的 AI 无武装舰队配对，而若两支 AI 科考/殖民舰队相遇，则直接产生 `dmgA = 0, dmgB = 0` 的永久死锁战斗。


* **病灶二：舰队 ID 字典序与派系 ID 比较方向错位，导致特定敌对舰队永久漏配（[engagement.js]([REDACTED]) 第 31–36 行）**
* 外层 `fleets` 按 `fleet.id` 字典序排列，内层循环 `for (let j = i + 1; j < fleets.length; j++)` 每对 `(A, B)` 仅单向访问一次，但第 36 行却错误添加了 `if (A.factionId > B.factionId) continue;`。一旦满足 `A.id < B.id` 且 `A.factionId > B.factionId`（例如 `'fac_553'` 的舰队 `'flt_100'` 与 `'fac_552'` 的舰队 `'flt_565'`），该舰队对在正向遍历时被跳过，又无反向遍历，导致同处一系的敌对舰队永远无法触发交战。


* **病灶三：`tactics.js` 存活判定失配（`!ship` vs `ship.status === 'destroyed'`）与 `applyHit` 提前返回，制造“不死僵尸单元”并锁死 `dmgA = 734.4`（[tactics.js]([REDACTED]) 第 34、118、134、151、289–290 行）**
* 当舰船被击毁时，[ship.js]([REDACTED]) 第 222–240 行 `destroyShip` **不会从 `world.entities.ships` 删除对象**，仅标记 `ship.status = 'destroyed'`。
* 然而 [tactics.js]([REDACTED]) 的 `movementBehavior`（第 34 行）、`targetingBehavior`（第 118、134 行）与 `firingBehavior`（第 151 行）全部只写了 `if (!ship)`，**漏检了 `ship.status === 'destroyed'**`；唯独 `applyHit` 第 290 行写了 `if (!tShip || tShip.status === 'destroyed') return;`（位于第 294 行累加 `battle.damageDealt` 和第 309 行 `target.destroyed = true` 之前）！
* **数学还原 `734.4` 冻结值**：玩家初始护卫舰搭载 `mod_railgun`（基础伤害 `34`，穿甲伤害），攻击敌方殖民船 `hull_supply`（护盾 `40`、装甲 `45`、结构 `560`，穿甲抗性分别为 10%/55%/0%，总有效生命约 `704.4`）。当护卫舰打出第 20 发命中（18 发普攻 + 2 发 `1.8×` 暴击 = `21.6 × 34 = 734.4` 点累计基础伤害）击穿结构，或当敌舰在 [HourlySystems.js]([REDACTED]) 第 57 行先被行星离子炮 `firePlanetaryIonBatteries` 场外击毁（`tShip.status = 'destroyed'` 但战斗内 `u.destroyed` 仍为 `false`）时，后续所有炮火继续锁定该“僵尸单元”射击，却在 `applyHit` 第 290 行被直接 `return` 丢弃，导致 `dmgA` 永远定格在 `734.4`、`target.destroyed` 永远无法置为 `true`！


* **病灶四：无武器单位贴脸逼退导致竞技场边界坐标锁死（[tactics.js]([REDACTED]) 第 59–76、100–101 行）**
* 无武器单位在 `targetingBehavior`（第 119 行）直接跳过，其 `u.targetShipId` 恒为 `null`；进入 `movementBehavior` 第 70–76 行后，`target === null` 的分支却命令其向最近敌舰全速贴脸（`desiredX = foe.x; desiredY = foe.y`），而有武器的护卫舰因 `d < bestRange * 0.55`（第 59 行）不断后退，最终被顶死在竞技场边界 `clamp(..., -100, ARENA.w + 100)` 与 `clamp(..., 30, ARENA.h - 30)` 角落，双方坐标彻底冻结。

function fleetHasWeapons(world, fleet) {
